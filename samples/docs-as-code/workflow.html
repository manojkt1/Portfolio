GitHub Actions Workflow

The pipeline triggers on every pull request that touches documentation source, and again on push to main, so broken links or a failing build are caught before they ship.

docs-quality.yml

name: docs-quality
on:
  pull_request:
    paths:
      - 'docs/**'
      - 'mkdocs.yml'
      - 'requirements.txt'
      - 'scripts/**'
  push:
    branches: [main]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - run: pip install -r requirements.txt
      - name: Check internal links
        run: python scripts/check_internal_links.py docs
      - name: Build documentation
        run: mkdocs build --strict

Why each step exists

  • Scoped triggers: the job only runs when documentation actually changed, keeping CI signal relevant.
  • Check internal links: scripts/check_internal_links.py walks every Markdown file under docs/ and fails the build if a relative link points to a file that doesn't exist.
  • Strict MkDocs build: mkdocs build --strict turns warnings (missing nav entries, unresolved cross-references) into build failures instead of silent gaps.
